# dependency-check-plugin

A Maven plugin that analyzes dependency parent chains and enforces a minimum version for specific parent POM groups across all modules in a multi-module build.

## Overview

In large Maven projects, transitive dependencies may pull in libraries that inherit from outdated parent POMs (e.g., an old Spring Boot BOM). This plugin traverses the full parent POM chain of every resolved artifact and flags dependencies whose parent version is below a configured minimum.

### What it does

- Builds the full **parent POM inheritance chain** for every resolved dependency
- Detects dependencies that use a parent from a **target group** (e.g. `org.springframework.boot`) with a version **below the minimum required**
- Supports **multiple target groups** (comma-separated)
- Produces structured **JSON reports** and a self-contained **HTML report** — both generated by the `aggregate` goal
- Works correctly with **maven-flatten-plugin** (reads POMs from reactor when available)
- Runs efficiently across **multi-module builds** with caching

## Plugin Goals

| Goal | Default phase | Aggregator | Description |
|------|--------------|:----------:|-------------|
| `check-versions` | `package` | | Checks parent POM versions for each module; saves per-module JSON results |
| `aggregate` | _(none)_ | ✓ | Aggregates per-module results; generates JSON and HTML reports. **Must be invoked explicitly.** |
| `dependency-tree-json` | `validate` | ✓ | Builds a full dependency tree (with parent chains) for all modules; no version check |

## Quick Start

### Step 1 — configure `check-versions` in the root `pom.xml`

```xml
<build>
  <plugins>
    <plugin>
      <groupId>net.olrecon</groupId>
      <artifactId>dependency-check-plugin</artifactId>
      <version>2.3.0</version>
      <!-- Plugin-level configuration: shared by check-versions AND the explicitly invoked aggregate goal -->
      <configuration>
        <targetGroupId>org.springframework.boot</targetGroupId>
        <minVersion>3.2.0</minVersion>
      </configuration>
      <executions>
        <execution>
          <id>check-versions</id>
          <goals><goal>check-versions</goal></goals>
        </execution>
      </executions>
    </plugin>
  </plugins>
</build>
```

> **Put `targetGroupId` and `minVersion` in the plugin-level `<configuration>`, not inside `<execution>`.**
>
> Configuration placed inside an `<execution>` applies **only to that execution**. The `aggregate` goal is
> invoked from the command line (`dependency-check:aggregate`), so it never sees execution-level settings
> and falls back to the defaults (`org.springframework`, `1.0.0`). The result: the report and
> `check-error.json` show the wrong target groups and minimum version.
>
> Alternatively, pass the same values on the command line, which applies to every goal in the invocation:
> `mvn verify dependency-check:aggregate -DtargetGroupId=org.springframework.boot -DminVersion=3.2.0`.
>
> Settings used only by `check-versions` (`includeGroups`, `excludeGroups`) may stay in the execution.
> `tempDir` must be identical for both goals, so keep it at plugin level (or leave the default).

### Step 2 — run with explicit `aggregate`

```bash
mvn verify dependency-check:aggregate
```

> **Why this order matters**
>
> `aggregate` is **not bound to any lifecycle phase** by design.
> When you append a goal after a lifecycle phase on the command line, Maven guarantees:
> 1. All reactor modules complete the lifecycle (including `check-versions` at `package`)
> 2. Only then the explicit goal (`aggregate`) runs on the root project
>
> Binding `aggregate` to a lifecycle phase (via `<execution>`) is **unreliable**: depending on
> the Maven version and project structure, the goal may execute before child modules complete,
> finding no results. Two-step invocation is the only guaranteed approach.

Output files in the root project's `target/`:

| File | Description |
|------|-------------|
| `target/check-error.json` | Aggregated violations (JSON) |
| `target/deps-tree-root.json` | Aggregated dependency tree (JSON) |
| `target/dependency-report.html` | Self-contained HTML report |

## Multiple Target Groups

To check against several parent group IDs, provide a comma-separated list in the plugin-level `<configuration>` (see [Quick Start](#step-1--configure-check-versions-in-the-root-pomxml)):

```xml
<configuration>
  <targetGroupId>org.springframework.boot,org.springframework</targetGroupId>
  <minVersion>3.2.0</minVersion>
</configuration>
```

or via command line:

```bash
mvn verify dependency-check:aggregate -DtargetGroupId=org.springframework.boot,org.springframework -DminVersion=3.2.0
```

A dependency is flagged when a parent from **any** of the listed groups appears in its parent chain with a version below `minVersion`. Group IDs are matched exactly, and the chain is walked up to the top: the **topmost** parent from a target group is the one whose version is checked.

## CI / CD Usage

### Single command (recommended)

```bash
mvn verify dependency-check:aggregate
```

### Fail the build on violations

```bash
mvn verify dependency-check:aggregate -DfailOnError=true
```

### Skip HTML report

```bash
mvn verify dependency-check:aggregate -DskipReport=true
```

### Fail-fast per module (without waiting for aggregate)

```bash
mvn verify -DfailOnError=true
```

This breaks the build as soon as the first module with violations completes the `package` phase.

## Goal Reference

### `check-versions`

Runs **per-module** during the `package` phase. Builds the dependency graph, traverses parent chains, and saves per-module result files to a shared temp directory.

| Parameter | Property | Default | Description |
|-----------|----------|---------|-------------|
| `targetGroupId` | `targetGroupId` | `org.springframework` | Target parent group(s), comma-separated. Matched **exactly** against the parent's groupId (no prefix matching); the whole parent chain is walked and the **topmost** matching parent is checked |
| `minVersion` | `minVersion` | `1.0.0` | Minimum acceptable parent version. Compared with Maven version ordering; a `-SNAPSHOT` suffix is ignored, while `-RC1`/`-M1` count as lower than the release. Unresolved `${...}` versions are never reported |
| `includeGroups` | `includeGroups` | _(all)_ | Comma-separated groupId prefixes to include |
| `excludeGroups` | `excludeGroups` | _(none)_ | Comma-separated groupId prefixes to exclude |
| `tempDir` | `tempDir` | `target/dependency-governance-temp` | Directory for per-module result files (relative to the root project, or absolute). Files are named `<groupId>.<artifactId>-tree.json` / `-errors.json` and the module's previous files are removed at the start of each run |
| `failOnError` | `failOnError` | `false` | Fail the build immediately if violations are found in this module |
| `debug` | `debug` | `false` | Enable verbose debug logging |

### `aggregate`

Runs **once** on the root project. Reads all per-module result files, merges them into aggregated JSON reports, and generates the HTML report.

**Must be invoked explicitly** — not bound to any lifecycle phase by default.

```bash
mvn verify dependency-check:aggregate
```

| Parameter | Property | Default | Description |
|-----------|----------|---------|-------------|
| `targetGroupId` | `targetGroupId` | `org.springframework` | Target group(s), comma-separated. Used for the report and JSON headers only — **must match** the value used by `check-versions` |
| `minVersion` | `minVersion` | `1.0.0` | Minimum acceptable parent version. Used for the report and JSON headers only — **must match** the value used by `check-versions` |
| `errorFile` | `errorFile` | `target/check-error.json` | Output path for aggregated errors JSON |
| `treeFile` | `treeFile` | `target/deps-tree-root.json` | Output path for aggregated dependency tree JSON |
| `reportFile` | `reportFile` | `target/dependency-report.html` | Output path for the HTML report |
| `tempDir` | `tempDir` | `target/dependency-governance-temp` | Directory with per-module result files (relative to the root project, or absolute); must match `check-versions`. Files of modules that are not part of the current reactor are ignored |
| `failOnError` | `failOnError` | `false` | Fail the build if any violations are found |
| `skipReport` | `skipReport` | `false` | Skip HTML report generation |
| `debug` | `debug` | `false` | Enable verbose debug logging |

### `dependency-tree-json`

Aggregator goal that runs **once** at the `validate` phase. Builds a complete dependency tree for all reactor modules enriched with parent POM chains. No version check performed.

| Parameter | Property | Default | Description |
|-----------|----------|---------|-------------|
| `outputFile` | `outputFile` | `target/dependency-tree.json` | Output path for the dependency tree JSON |
| `includeScopes` | `includeScopes` | _(all)_ | Comma-separated scopes to include |
| `excludeScopes` | `excludeScopes` | `system` | Comma-separated scopes to exclude |
| `includeOptional` | `includeOptional` | `false` | Include optional dependencies |
| `includeTestScope` | `includeTestScope` | `false` | Include test-scoped dependencies |

## Execution Order Explained

```
mvn verify dependency-check:aggregate
       │                    │
       │  [reactor: all modules complete verify]
       │                    │
       ├─ module-a: package → check-versions (writes temp files)  ┐
       ├─ module-b: package → check-versions (writes temp files)  │ verify phase
       ├─ module-c: package → check-versions (writes temp files)  ┘
       │
       └─ [explicit goal runs after reactor completes]
          aggregate → reads all temp files → JSON + HTML report
```

Specifying a lifecycle phase **and** an explicit goal in one Maven invocation is the standard Maven pattern for post-reactor aggregation. Maven processes the entire reactor through the specified phase first, then runs the explicit goal.

---

## HTML Report

The HTML report is generated automatically by the `aggregate` goal. It is a fully self-contained file (no internet connection required) and includes:

- **Summary cards** — build status (PASSED / FAILED), total violations, modules with errors, target groups, minimum version
- **Per-module violation tables** — library coordinates, found parent version, minimum expected, who introduced the dependency, full parent chain
- **Success banner** — shown when no violations are found
